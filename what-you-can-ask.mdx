**Your bot is your own Claude Code session with a face, a voice, ears and hands.** So the
honest answer to "what can it do" is: whatever that session can do, plus it's in the room
with you.

This page is the ladder. Everything on it has worked in real calls — the top rungs daily,
the bottom rungs validated with our own bots so far. Say the words in the left column
out loud, mid-call. Start at the top. The bottom is real too, it just takes longer.

<Note>
  **You talk to it like a person, not a command line.** There's no syntax. "Hey, can you pull
  up that page?" works exactly as well as anything below.
</Note>

## 1 · The basics — talking

| Say this | What happens |
|---|---|
| "What do you think?" | It answers out loud, in its own voice |
| "Just listen for a while" | It goes quiet until you name it (*passive* mode) |
| "Say nothing, just take it in" | It stops speaking entirely (*silent* mode) |
| "Jump in when you have something" | Back to normal (*active* mode) |
| "Can you use a different voice?" | It switches voice mid-call |

### Which mode should I use?

Nobody tells you these exist until you need them — so here's the whole menu. (A beta user
independently invented passive mode by muting her bot and driving it by chat; you can just
ask for it.)

<Warning>
  **In any meeting with people who didn't ask for your bot, start in passive.** The app
  currently starts bots in *active* — so this is one sentence you have to say, and it is the
  single highest-value sentence in this page: **"Only speak when I name you."**

  This isn't caution for its own sake. Our most experienced user put it plainly: *"I like
  this a LOT when I know she's staying quiet."* The value isn't the bot being quiet — it's
  **you knowing in advance that it will be.** In the other direction, an active bot in a
  10-person room re-introduced itself four times and filled a silence unasked, and two
  strangers independently called it aggressive. Predictable beats impressive.
</Warning>

| Your situation | Mode | Say |
|---|---|---|
| Solo or with someone who's in on it — bot is a full participant | **active** (what the app starts in) | — |
| Real meeting with other humans; bot should contribute only when called on | **passive** | "Only speak when I name you" |
| Bot should work (whiteboard, files, research) but never talk | **silent** | "Go silent — keep working, no talking" |
| Someone's presenting or interviewing; bot keeps references on screen, says nothing | **ambient** | "Just illustrate while we talk" ([details](/ambient)) |
| A call you don't host, room full of strangers | **passive or silent** | see [guest etiquette](/guest-etiquette) |

## 2 · Show me something

| Say this | What happens |
|---|---|
| "Pull up their website" | Shares a real, live browser tab into the call |
| "Put that on the whiteboard" | Writes text, lists, notes to the shared board |
| "Scroll down" / "go back to the top" | Drives the thing it's already sharing |
| "Stop sharing" | Drops the share |
| "Just illustrate while we talk" | [Ambient mode](/ambient) — silently keeps references on screen |

## 3 · Look at things

| Say this | What happens |
|---|---|
| "What are we looking at?" | It screenshots the call and tells you what's on screen — including someone *else's* share |
| "Read the chat" | It reads Meet chat and can post there too |
| "What did I say about that earlier?" | It has the transcript of the call so far |

## 4 · Make things — this is the part people forget

Your bot is a full coding session. Everything Claude Code does, it does *while you talk*:

| Say this | What happens |
|---|---|
| "Fix that bug we just described" | Writes the code, on your machine, during the call |
| "File that as an issue" | Opens a real GitHub issue |
| "Make me a picture of that" | Generates an image (with your own API key) |
| "Build a quick page showing this" | Writes it, and can share the result on screen |

<Tip>
  This is the actual pitch. **Don't meet about the work — do the work in the meet.** The
  best calls end with the thing built, not with a list of who'll build it.
</Tip>

## 5 · Remember the call

| Say this | What happens |
|---|---|
| "Write that down" | Notes to the whiteboard or a file |
| *(nothing — automatic)* | When it leaves, it gets an **after-call phase**: transcript still readable, and it does whatever its `CLAUDE.md` says. By default, a summary in a folder. |
| "Write up what we decided" | A summary, a receipt page, or whatever you've told it to produce |

## 6 · Give it an identity

| Say this | What happens |
|---|---|
| "Change your face to 🎧" | New emoji, immediately |
| "Be more like a skeptical editor" | Changes register for the rest of the call |
| "Write yourself a card" | A [Botfile](/botfile) — one markdown file that makes it the same character next time, on any machine |
| "Switch to my other bot" | One leaves, another joins (~30s — names lock at join, so it's a swap, not a rename) |

## 7 · The deep end

These take minutes, not seconds — but they happen *during* the meeting:

- **"Make a video of this call"** — a bot with image/video API keys can generate a narrated recap and screen it before anyone hangs up. Yes, really; this is how our own build-log videos get made.
- **"Bring your agent too"** — everyone installs the app and brings their own bot. Measured on Aug 6 and Aug 8: **four bots in one room, no degradation.** What gets crowded at that size isn't the machine, it's the conversation — put all but one in **passive mode** so they answer only when named.
- **"Turn this into a tool"** — describe a utility out loud, get a working script committed before the call ends.

## What it can't do

Being straight with you, because the failures are worse than the gaps:

- **Change its name mid-call.** Names lock when it joins Meet. Swapping means one bot leaves and another joins.
- **Hear anything before it joined.** No memory of the call before its arrival unless you tell it.
- **Work without your keys.** It uses *your* Claude subscription and *your* API keys. We don't host your calls or hold your account.

If something misbehaves mid-call, [troubleshooting](/troubleshooting) is written from real failures — and `jimmy@vibeconf.app` reaches a human.
